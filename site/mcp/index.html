Connect your MCP client

Install bruster and its platform runtime first. Confirm that bruster is on the client’s PATH, or use the absolute executable path in its configuration. Your MCP client launches and manages the browser process over stdio.

OpenCode

Add the local server from your project:

Terminal
opencode mcp add bruster -- bruster --mcp --quiet
opencode mcp list

OpenCode V2 configuration uses mcp.servers. The equivalent entry in opencode.jsonc is:

opencode.jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "bruster": {
        "type": "local",
        "command": ["bruster", "--mcp", "--quiet"]
      }
    }
  }
}

OpenCode reloads saved configuration automatically. Use /mcps to inspect the connection. OpenCode MCP documentation ↗

Claude Code

Terminal
claude mcp add bruster -- bruster --mcp --quiet

Ask Claude to open a page, inspect its snapshot, and take a screenshot using bruster’s tools.

Claude Desktop and Cursor

Add the server under mcpServers in Claude Desktop’s claude_desktop_config.json or Cursor’s .cursor/mcp.json:

MCP configuration
{
  "mcpServers": {
    "bruster": {
      "command": "bruster",
      "args": ["--mcp", "--quiet"]
    }
  }
}

Merge this entry with your existing servers. Desktop applications may need an absolute path such as /home/you/.local/bin/bruster or /Users/you/.local/bin/bruster.

Codex CLI

Terminal
codex mcp add bruster -- bruster --mcp --quiet

The client launches bruster in MCP mode and makes its browser tools available to the agent.

VS Code

Add a stdio server to .vscode/mcp.json:

.vscode/mcp.json
{
  "servers": {
    "bruster": {
      "type": "stdio",
      "command": "bruster",
      "args": ["--mcp", "--quiet"]
    }
  }
}

Use VS Code’s MCP server controls to start the server and inspect its tool list.

Want to see the browser?

MCP mode moves the windows off-screen by default. Append --visible to the arguments to watch the session. Add --profile followed by a directory path to persist cookies and storage.

Use the Docker image with your MCP client

The Docker Hub image includes the Linux browser runtime and virtual display for amd64 and arm64. Install and start Docker on the machine that runs your MCP client, then pull the image before the first connection:

Terminal
docker pull ilyastmn/bruster:latest

For Claude Desktop or Cursor, merge this entry into your MCP configuration. The client starts Docker as a stdio subprocess; the image already defaults to MCP mode.

Claude Desktop / Cursor · Docker
{
  "mcpServers": {
    "bruster": {
      "command": "docker",
      "args": ["run", "--rm", "-i", "ilyastmn/bruster:latest"]
    }
  }
}

Keep -i and omit -t so JSON-RPC stays on stdin/stdout. Ensure docker is on the client’s PATH, or use its absolute path. Browser rendering stays inside the container’s Xvfb display. See image tags, launch options, and native JSON-lines usage →

Troubleshooting

The client cannot find bruster

Use the absolute executable path in command. GUI clients do not always inherit your terminal’s PATH. On Windows, use the path to bruster.exe and escape backslashes in JSON.

Linux fails to start without a display

Install WebKitGTK 4.1, Xvfb, and xauth. Hidden mode still needs a display; bruster tries xvfb-run when DISPLAY is unset. See Linux and CI setup. Temporarily remove --quiet to inspect diagnostic output on stderr.

An interaction behaves differently from a human click

Bruster dispatches synthetic DOM events. Cross-origin iframes, native file dialogs, OS shortcuts, and some native control behaviors are outside its scope. Read the limitations and tool comparison when choosing a browser backend.
