This lesson gets the right program onto your computer. Take it one step at a time. Your goal is simple: run Bruster’s test help command and see a list of testing options.

Use a build that includes the test runner

The v0.3.6 release archives do not include the .bru runner used in this course. Build the current source using the steps below, or ask a colleague to provide a build for your operating system. The help check at the end confirms that you have the right program.

You can continue reading the lessons before setup is finished. The first four lessons only need a browser.

1. Understand the tools you will use

A terminal is a window where you type an instruction and press Enter to run it. On Windows, we will use PowerShell. On a Mac, use Terminal. Linux usually has an application called Terminal too.

A source build turns a program’s source files into an application you can run. Bruster is written in the Rust programming language. You will install Rust’s build tools and use a tool called Cargo to build the existing project. You do not need to write Rust or edit Bruster’s source files.

Copy only the command itself from a code box. A terminal may display a prompt such as $ or PS C:\Users\Ada>. That is the terminal showing where it is ready for input; it is not part of the command.

2. Install the build tools for your computer

Open the section for your operating system. You only need to install these tools once, not before every test.

macOS

Open Terminal from Applications → Utilities. Run the following command and follow the Apple installer if it appears. It installs Apple’s command-line development tools.

xcode-select --install

Then open the official Rust installer page and follow its macOS instructions. Use the default installation unless you already maintain a Rust setup. Close and reopen Terminal afterward.

Bruster uses the Mac’s built-in WKWebView browser runtime.

Windows

Open the official Rust installer page, download its Windows installer, and follow the prompts. Rust needs the Microsoft C++ build tools on Windows. If the installer directs you to install them, follow that step before continuing. The relevant Visual Studio Build Tools workload is Desktop development with C++.

Bruster also needs the Microsoft Edge WebView2 Runtime. It is already present on many Windows computers. Install it from Microsoft if it is missing.

Close and reopen PowerShell after installing Rust so the new commands are available.

Ubuntu or Debian Linux

Open Terminal and install the native build dependencies. Run each line separately:

sudo apt-get update
sudo apt-get install build-essential pkg-config libwebkit2gtk-4.1-dev libgtk-3-dev xvfb xauth

sudo may ask for your computer password. The terminal may show no characters while you type it. That is normal.

Next, follow the Linux instructions on the official Rust installer page. Reopen Terminal afterward. Other Linux distributions use different package names; use the platform documentation for those systems.

WebKitGTK renders the page. Xvfb can provide a display when there is no desktop session. On a normal desktop, start with the existing display.

In a new terminal window, run:

cargo --version

You should see a version line beginning with cargo. If the command is not found, finish the Rust installation and reopen the terminal before continuing.

3. Download the source and build it

  1. Download the current Bruster source ZIP.
  2. Extract the ZIP. Find the folder containing Cargo.toml; it is normally called bruster-main.
  3. Open a terminal in that folder. In Windows File Explorer, open the folder, type powershell into its address bar, and press Enter. On a Mac, you can use the folder’s Services → New Terminal at Folder menu. Many Linux file managers have Open in Terminal.
  4. Run the build command below and wait for it to finish.
cargo build --release --locked

The first build downloads dependencies—other software Bruster needs—and prints many lines of progress messages. A successful build ends with a “Finished” message. If the command reports that it cannot find Cargo.toml, the terminal is in the wrong folder.

4. Make a practice folder and check the program

Create a folder named bruster-practice in Documents. Inside the source folder, open target, then release. Copy the program named bruster on macOS/Linux, or bruster.exe on Windows, into your practice folder.

Open a new terminal in bruster-practice. The commands below mean “run the program in this folder and show its test help.”

macOS / Linux
./bruster test --help
Windows PowerShell
.\bruster.exe test --help

Look for Usage: bruster test FILE.bru and options such as --visible and --output. That is your setup checkpoint. An ordinary Bruster help screen without the test command is not the same result.

Ready to continue

You have a practice folder containing the Bruster program, and the test help command works. If a build fails, save the last error message and ask for help with that specific error. You do not need to understand every build log line to explain where you got stuck.
