You can learn to test a website without already knowing how to program. Start by noticing what a page does. Then learn how to ask a browser to repeat a small check for you.

This course takes you from your first manual check to a small set of automated tests. There are twenty lessons, including this one. Each lesson explains one idea, shows a concrete example, and gives you something to try.

You will use a simple practice form throughout the course. You will not need to invent an application or find sample data. The same familiar form will help you see what each new command changes.

What will you be able to do?

By the end, you should be able to describe a website check in plain English, turn it into a short Bruster test file, run it, and explain the result. You will also learn how to find a field on a page, test missing information, and keep useful screenshots.

Imagine a colleague asks, “Does our form still work after yesterday’s change?” You will have a way to answer with a specific check: enter a name and project, submit the form, and confirm that the receipt contains the right project name.

That is a useful first goal. Testing an entire large application comes later. A small check that you understand is a better starting point than a large script that you cannot explain.

How the course works

Lessons 1–4: think like a tester

Learn what a test is, explore the practice page, and write a short plan. You only need your normal browser for these lessons.

Lessons 5–8: set up and run

Get a test-ready copy of Bruster, make a plain-text file, run it, and understand its few lines. Installation gets its own lesson because it can take longer than the first test.

Lessons 9–14: build useful checks

Find controls, fill forms, check results, change options, and try invalid input. Learn to give every test a fresh start.

Lessons 15–20: make testing a habit

Understand waiting, keep evidence, investigate failures, and adapt your approach to another website. Finish with a five-check project.

What is Bruster?

Bruster is a program that can control a browser window. You give it a small text file containing instructions. It follows those instructions and reports whether your checks passed.

The instructions are written in a DSL. That stands for “domain-specific language”: a small language for one job. Here, the job is browser testing. You will see commands such as fill, click, and expect text. We will explain each one before asking you to use it.

The course uses Bruster’s .bru test runner from source builds. The released v0.3.6 archives predate that runner. Lesson 5 explains how to get the right build, including the final check that confirms you have it.

A comfortable way to learn

Keep this course in one tab and the practice page in another tab. Read a short section, try the action, and compare what you saw with the explanation. You can use the contents menu to return to a lesson whenever you need it.

When you meet an unfamiliar word, look for its explanation nearby. At the end of the course, a small glossary brings the important words together. There is no account or completion timer. Your progress is the work you can now do.

Try it now

Think of one thing you often do on a website: search for an item, send a message, or complete a form. Write one sentence describing what should happen afterward.

For example: “After I submit a valid project name, I should see that name in a confirmation.” Keep this sentence. You have already begun a test plan.

Before you move on

You do not need to memorize any commands yet. Be ready to describe one website action and the result you would expect from it.
